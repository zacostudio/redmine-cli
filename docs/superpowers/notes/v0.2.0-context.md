## 결정 사항

- `RedmineClient` 에 새 HTTP 메서드 도입하지 않음. 기존 `get`/`post`/`put_no_content`/`delete` 만 사용 (디자인의 비범위 항목).
- 단수/복수 컨벤션:
  - write 가 있는 리소스: 단수 + 서브커맨드 (`issue`, `version`, `membership`, ...).
  - read-only enum/메타: 복수 + 단일 커맨드 (`roles`, `custom-fields`, `document-categories`, ...).
- News create 는 Redmine 5+ 에서만 동작. CLI 에는 노출하되 4.x 서버에서는 그대로 HTTP 오류 표면화.
- Queries 는 REST API 자체가 read-only 라 list 만 노출.
- `issue note` 는 `issue update --notes` 와 중복이지만 편의 진입점으로 유지.

## 작업 진행 메모

- **2026-05-16, A1~A4**: 단순 list/enum 패턴. 기존 `enums.rs` 답습. search는 `q` 외 `scope`, `all_words`, `titles_only` 옵션 노출. `RedmineSearchResult` 의 `type` 필드는 Rust 예약어라 `kind` 로 매핑 후 출력에서 다시 `type` 으로 노출.
- **2026-05-16, B1 version**: 표준 CRUD. status/sharing 은 enum이지만 String 으로 노출(Redmine 4.x/5.x 차이 흡수).
- **2026-05-16, B2 membership**: user/group 양쪽 지원. CLI에서 `--user` 와 `--group` 은 mutually exclusive (`conflicts_with`). 둘 다 user_id 필드로 직렬화(Redmine 관례).
- **2026-05-16, B3 news**: list/show 만 4.x 호환, create 는 5+ 전용. 실패 시 HTTP 오류 그대로 표면화.
- **2026-05-16, B4 file**: 업로드는 두 단계 (`/uploads.json` 으로 토큰 받기 → `/projects/:p/files.json` 으로 등록). 두 번째 응답이 빈 본문일 수 있어 신규 헬퍼 `post_no_content` 도입. 디자인의 "신규 HTTP 메서드 안 함" 비범위는 새 HTTP method 추가를 의미하므로 본 추가는 비범위 위반 아님 (응답 처리 방식만 다른 헬퍼).
- **2026-05-16, B5 query**: REST API 자체가 read-only. 단일 list 커맨드만.
- **2026-05-16, B6 wiki**: `--text -` 로 stdin 본문 입력 지원 (위키 본문이 길어 inline 인자 부적합). title 은 URL 인코딩 필수 (`urlencoding::encode`). create/update 둘 다 PUT 으로 처리 (Redmine 관례).
- **2026-05-16, B7 group**: admin 전용. add-user/remove-user 는 별도 엔드포인트 (`/groups/:id/users.json` POST, `/groups/:id/users/:uid.json` DELETE).
- **2026-05-16, C1 my-account**: `RedmineUser` 에 `admin`/`created_on`/`last_login_on` 필드 추가. Option 타입이라 기존 응답과 호환.
- **2026-05-16, C2+C3**: 한 커밋에 묶음 (둘 다 `issues.rs` 한 파일에 추가되는 small additive 변경). note 는 기존 `update_issue` 재사용. watcher 는 신규 client 메서드 두 개.
